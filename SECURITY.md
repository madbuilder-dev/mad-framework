# Security policy

Mad Framework runs inside business applications in production, so we take security reports seriously and appreciate the time you spend on them.

## Supported versions

Fixes are released on the latest `5.x` version. MadBuilder ships each release to the apps it generates, so staying current is the way to receive them.

## Reporting a vulnerability

Please **do not open a public issue** for security problems.

Report it privately through GitHub: open the **Security** tab of this repository and choose **Report a vulnerability**. Include as much of the following as you can:

- the framework version (the `VERSION` file) and your PHP, Laravel and database versions;
- the component, endpoint or class involved;
- steps to reproduce, or a proof of concept;
- the impact you expect (data exposure, privilege escalation, remote code execution…).

We will confirm that we received the report, keep you informed while we investigate, and credit you in the release notes if you wish. Please give us a reasonable time to ship a fix before disclosing the issue.

Problems in the MadBuilder platform itself (the Studio, the agent, MadCloud hosting) can be reported through the same channel.
